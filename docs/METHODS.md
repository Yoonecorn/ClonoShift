# Methods and bounded interpretation

ClonoShift Extended is the ClonoShift-developed corrected extension and qualified hybrid: the validated Core-fitted exponent and linear minimum frequency are held fixed while the corrected Poisson workflow conditions on observation, excluding the unobserved (0,0) pair, and uses a symmetric midpoint/log-response prior. The finite prior and effect threshold are supplied by the user, not learned. Fitted-parameter uncertainty is not propagated. The optional omission certificate bounds cumulative omitted-state error under its specified numerical budgets; it is not a certificate of model adequacy or biological calibration. Unresolved results are refused rather than promoted.

ClonoShift Core is a bounded NoisET-compatible Rust reimplementation/port of the Poisson fit and response formulation with the established first-observed-category conditioning and known legacy C2 and response-prior quirks. Core's `tail_P_s_le_zero` includes the zero atom and is not a contraction probability. The native optimizer is not a reproduction of the reference optimizer; endpoint compatibility is bounded and does not guarantee convergence or global optimality on arbitrary inputs.

A configuration for the illustrative fit is of this form; substitute the successful fit's exact exponent and **linear** minimum frequency (10 raised to its log10 minimum), and a valid path to that fit's `model.json`:

```json
{"noise":{"model":"poisson","parameter_order":["exponent","minimum_frequency"],"parameters":[-1.364581788686987,0.003214439795261944],"source":"qualified_legacy_fit","source_reference":"synthetic replicate example","legacy_model_file":"fit/model.json"},"response_prior":{"response_probability":0.2,"scale":1.0,"points":33,"stride":1,"maximum_shift":6},"effect_delta":0.3}
```

The fitted `parameters.tsv` labels its values `exponent` and `log10_minimum_frequency`; this descriptive labeling differs from the historical compatibility table while the fitted values are unchanged. The config's model path is resolved relative to the JSON file. Admission verifies model identity, fit success, C2 and parameter agreement. Both-mode execution requires this model's hash to match one of the two Core model files. Different response priors, grids, conditioning and summaries prevent interpreting sign agreement as direct biological equivalence. The comparison uses Extended posterior mean and Core median only as descriptive signs; missing medians are unavailable.

Both result tables are complete for successfully analyzed input clones. Core-specific columns include the zero-inclusive tail and mean, mode, and interval summaries. Extended-specific columns contain probabilities for positive, negative and within-delta regions, posterior mean and interval, evidence and numerical status. `comparison/summary.tsv`, `agreement.tsv`, `disagreement.tsv`, `unavailable.tsv` and `run-metadata.json` preserve status and reasons. The metadata records input and model/configuration hashes, parameter settings, version, warnings and status. Results have `COMPLETED`, `REFUSED`, `FAILED` or `UNAVAILABLE` states. Unexpected model failures do not remove a completed other-model result. The outer no-replace rename is atomic; abrupt process death may leave a private staging directory, and parent-directory durability after power loss is not guaranteed.

The retained research interfaces do not establish biological calibration, empirical biological FDR, family-wide BCR labels, or count-only identification of biological versus technical variation. Automatic corrected fitting and other experimental interfaces are not the default Extended model. No biological winner or merged verdict is produced.
